# Decisions

One line per methodological decision: what you chose, why, and what it changed.
Agents append here via the `/new-feature` skill; you append here by hand.

- Exclude `casual`, `registered`: they sum to `cnt` exactly. Leaky model R^2 1.000 -> honest ridge 0.583.
- Exclude `cnt_2d_bfr`: a shipped 2-day lag we cannot test the alignment of. Build our own lags instead.
- Exclude `instant`, `yr`, `days_since_2011`: time indexes let a tree predict a flat constant past 2011 and a linear model extrapolate a trend we have no grounds for.
- Split 2011 / H1 2012 / H2 2012 by date. Test set touched once, after all feature work.
- Report mean and persistence baselines with every score. Persistence (test R^2 0.510, MAE 840) is within 0.07 R^2 of ridge and beats it on MAE; that caveat goes in the report.
- 2026-11-25: Added `weather_severity_lag_1` (yesterday's weather severity, calendar shift after `reindex_to_calendar`). Availability: for date d it is d-1's recorded weather, known before d starts. Why this one: persistence misses worst on the day after bad weather (2011-04-16 BAD, 795 rides; 04-17 GOOD, 3,744). One pre-chosen candidate, one run. Validation R^2 ridge 0.6475 -> 0.6670 (+0.0195), hgb 0.2185 -> 0.2437 (+0.0252); ridge valid MAE 832.9 -> 803.9. Kept: above the 0.01 floor in the new-feature skill (a floor, not a significance test; 182 validation days). `make train` also writes test numbers, but they were not used for this decision.
- 2026-11-25: Every raw column classified in `src/config.py`, and the model's inputs must equal `DECLARED_FEATURES` (an allowlist on top of the `FORBIDDEN` denylist). Chosen failure: loud in both directions. A new raw column, a leaked column under a new name, or a feature that vanishes all fail a test; the cost is that every new feature must be declared in `ENGINEERED_COLS`.
- 2026-11-25: Added `test_encode_weather_fails_loudly_on_unknown_labels` after seeded fault 3 (raise removed) left the whole suite green.
- 2026-11-25: Raw data guarded by SHA-256 (`RAW_SHA256`; checked by `make data` and `test_raw_file_is_unmodified`), plus a Stop hook that runs the full suite. Seeded fault 4 (a Bash `cp` into data/raw) passed every starter guard and moved ridge test R^2 0.6124 -> 0.5741.
- 2026-11-25: Exercise 4, validation only (`make ex4-valid`, `src/train.py --target`). Tried three target transformations for ridge and hgb: cnt / cnt_roll_7 ("ratio"), its log, and cnt - cnt_lag_1. hgb valid R^2 0.2437 -> 0.7591 / 0.7161 / 0.6254; ridge 0.6670 -> 0.4305 / 0.5472 / 0.6675. Mechanism: 39% of H1-2012 days exceed the 2011 maximum of cnt, but 0% of validation ratios fall outside the 2011 ratio range (0.158-1.878). Chose "ratio" for the one test run. Judged defensible as a forecasting setup: it divides by a level known at d, is scored in rides and was fixed before test. Not defensible as "trees beat ridge": the same transform hurts ridge, so the comparison is between two (model, target) pairs. `reports/metrics.json` stays untransformed.
